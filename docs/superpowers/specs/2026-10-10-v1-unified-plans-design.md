# 日子芽 V1.0.0 · 统一计划模块设计

日期：2026-10-10（Asia/Shanghai）。基线：`main` 的 `b016bcbc0f146ea6d9fe257b734700689de5cb51`。

状态：用户已确认产品规则、统一表方案、迁移原则、页面、统计与提醒方向；本文是完整设计的审阅稿。仅提交设计，不表示 V1 已实现、测试通过或发布。现有应用仍为 0.1.1 / versionCode 2 / Room schema v5。

## 1. 决策与范围

用户选择方案 2：以统一计划主表、仓库、用例和页面替代长期并存的 Todo / Schedule 实现，而不是只把两个旧页面放进一个 Tab。

已确认：

- 无日期的事项归为待办；有截止时间、起止时间或全天日期的事项归为日程。两类属于同一个「计划」模块。
- 待办添加截止日期后自动归入日程，更新同一记录，保留内容、关联和完成状态。
- 所有计划可以完成、撤销完成；重复日程的完成作用于整个系列，不实现逐次完成。
- 保留旧待办和日程数据，保留标签、父子关系、完成时间、地点、参与者、颜色、时区、重复规则与取消例外。不按标题去重。
- 底部导航为「计划 / 打卡 / 订阅 / 设置」；保持 Kotlin、Compose、Material 3、MVVM、Clean Architecture、Hilt、Room、Flow/StateFlow 与离线运行。
- 改版目标版本为 1.0.0，保留 `com.example.lifemanager` 安装身份和「日子芽」名称/图标；主机使用 JDK 25，设备字节码目标继续为 17。

本设计替代原 `android-app-prompt.md` 中独立待办/日程入口、分立业务模型和相关提醒设置约定，其余安全、离线、测试、无障碍等约束继续有效。原文档中的嵌入式开发指令不扩展本次已确认范围。

不纳入本次：云同步、账号、支付接入、打卡提醒/暂停/归档、批量操作、子任务编辑入口、拖拽排序/改期、日历双指缩放，以及打卡/订阅整页视觉重做。已存在的子任务存储关系必须保留，不因没有编辑入口而删除。不能以 V1 命名宣称真机、稳定 60fps 或正式签名已验收。

## 2. 时间与分类

分类从有效时间模式推导，不另存一个可能与时间字段矛盾的「待办/日程」开关。

| 时间模式 | 有效字段 | 分类与日历表现 |
| --- | --- | --- |
| `NONE` | 无有效日期/时间 | 待办，不进入日历，不排提醒 |
| `DEADLINE` | `dueAt`，或仅日期的 `dueDate`，二者互斥 | 日程；截止日期上显示点状事项，不生成虚构开始时间 |
| `TIMED` | `startAt`、`endAt`；结束晚于开始 | 日程；按真实时间区间显示 |
| `ALL_DAY` | `allDayStartDate`、`allDayEndDate` | 日程；按全天日期显示，结束日期含当天 |

Instant 持久化为 Long 毫秒，LocalDate 为 Long epochDay；`timeZone` 保存有效 IANA ZoneId。仅日期不转换为午夜 Instant。旧全天日期使用闭区间，不改成排他结束日。

无日期转为截止模式只改时间相关字段和 updatedAt，主键不变。首次添加日期不重置完成状态、创建时间、优先级、标签或备注。提供显式移除日期操作可回到待办；对重复或区间计划必须确认将停止重复与提醒。V1 的移除日期保留原时间/重复字段作为非活动配置，便于以后编辑，不自动复活；有效模式为 NONE 时任何保留参数都不得排程或参与冲突。

更改时间模式前展示将停用的参数，保留编辑草稿；重新启用必须选择合法日期并确认有效重复规则。旧记录中未参与当前模式的非空字段也无损保存，不能在第一次打开编辑页时默默归零。

V1 首批沿用现有重复功能范围：TIMED / ALL_DAY 支持已有每日、每周、每月、每年和自定义规则；NONE / DEADLINE 不启用重复。自定义间隔、星期与结束日期即使没有完整编辑控件，也必须保留并正确计算，不展示尚未实现的配置按钮。

## 3. 统一数据模型

目标为 Room schema v6。主记录统一进入 `plans`；旧 Todo / Schedule DAO 不再作为正常业务读写路径。

`plans` 字段组：

- 身份和内容：`id: Long` 自增主键、title、`description: String?`、priority、color、location、participants。
- 时间：timeMode、dueAt、dueDate、startAt、endAt、allDayStartDate、allDayEndDate、timeZone。
- 完成：isCompleted、completedAt。
- 重复：repeatRule、repeatInterval、repeatDaysOfWeek、repeatEndDate。
- 提醒：`reminderEnabled: Boolean`、`reminderMinutes: Int?`；原始提前分钟与实际启用状态分开保存。
- 关系/排序/审计：parentId、sortOrder、createdAt、updatedAt。

`isAllDay` 由模式推导；旧日程 note 无损进入 description。标题/备注不在迁移时 trim 或拼接。无来源值的新增字段按明确缺省初始化，不凭空创建业务内容。

具体新增缺省：旧日程的 priority=NONE、parentId=null、sortOrder=0；旧待办的 color=`0xFF246956`、location/participants=null、repeatRule=NONE、repeatInterval=1、重复星期/结束日期=null，其原 dueAt 与所有旧字段不变。dueDate 是新版仅日期截止字段，全部旧记录初始化 null；新建默认标题/备注由用户填写，不能补业务示例。旧待办的缺失时区只由调用方注入的转换 ZoneId 填充，升级取设备时区，旧文件导入取本次恢复设备时区，并向用户说明该来源没有保存时区。

校验分清有效参数与无损保留的非活动参数：合法 timeMode 的有效字段必须完整；保留的其他日期/重复参数不参与计算，不能因为当前模式未使用就删除。现有时间字段中非法类型/日期/时区仍拒绝，不以“非活动”豁免文件安全校验。

关联表：

- `tags`：沿用原标签数据和 ID。
- `plan_tag_cross_ref(planId, tagId)`：联合主键、有效外键。
- `plan_exceptions(planId, occurrenceDate, isCancelled)`：重复取消例外，不用它表达完成整个系列。
- `plan_legacy_refs(source, legacyId, planId)`：来源只能为 TODO / SCHEDULE；来源与旧 ID 联合唯一，planId 唯一且指向 plans。新建计划不需要来源映射。该表是兼容关系，不是第二套业务表，纳入新版备份。

父子关系仅允许树。迁移保留原关系；删除父计划时解除其子计划的 parentId，不默默删除子计划；同事务清理本计划标签、例外与来源映射。完成父计划不自动完成子计划。

打卡、订阅、实际扣费与相关外键、金额精度、币种规则不变。设置表更新计划提醒字段；维护元数据继续存在。

## 4. v5 → v6 升级契约

保留原 v1→v5 升级链，并增加显式 5→6 Migration。新安装直接创建 v6。不能使用 fallbackToDestructiveMigration、数据库文件覆盖或清库重建。

升级过程在 Room 管理的迁移事务内完成：

1. 创建 plans、计划关联表和来源映射表，逐条读取旧记录，不将整库装入内存。
2. 按 TODO 旧 ID 升序，再按 SCHEDULE 旧 ID 升序分配新的 Long 自增 ID，同时保存来源映射。禁止用 `oldId + maxTodoId`，避免旧 Long 大值溢出；插入失败或映射冲突立即中止。
3. 旧 todos：dueAt 为 null 映射 NONE，否则 DEADLINE；逐值保存完成记录、父 ID 待映射、标签、排序和时间戳。timeZone 使用升级时设备 ZoneId，dueAt 原始毫秒不变。
4. 旧 schedules：按 isAllDay 映射 ALL_DAY / TIMED；保存原始时间、时区、note、地点、参与者、颜色、完整重复配置和例外；完成初始化 false / null，不伪造完成历史。
5. 所有主记录先以 parentId=null 插入，再通过 `(source, legacyId)` 重映射父子、标签与取消例外；不依赖父 ID 小于子 ID。相同数字 ID 或相同标题的两条旧记录必须仍是两条计划。新关联使用有效外键，迁移结束执行外键检查。
6. 校验 plans 总数等于原两表总数、来源映射一一对应、每字段转换一致、标签/例外/父子完整、无孤儿或环；校验打卡和订阅的逐字段快照未变化。
7. 迁移提醒偏好，保留其有效启停状态；原库若缺少/损坏设置或维护行，明确失败，不暗中补默认值。
8. 在事务内推进本机维护世代一次，使升级前的广播/草稿令牌不能对新 ID 生效。Long 世代耗尽明确拒绝，不回绕。
9. 校验成功后，按依赖顺序删除已复制的旧标签关系、例外、todo/schedule 表并完成 schema 校验。这是显式、已校验的数据转换，不是 destructive fallback；任何 SQL、校验或 schema 错误均使迁移整体回滚。

升级失败不得自动删除旧库、修改旧数据或卸载应用。提供可理解的错误与重试/支持说明；提醒用户安装升级前先从旧版导出备份，不声称应用迁移前一定能访问外部保护文件。

迁移成功后的回退策略是发布更高 versionCode 的 V1 前向修复，并可在 V1 中恢复有效 v1/v2 备份，不是把已升级设备安装回 V0。开发分支可回退不等于真实设备的 schema 可以降级；不提供会丢失新字段的 6→5 迁移。

迁移完成不等于 Android 闹钟已清理。所有业务初始化、Worker 与 Receiver 都必须先等数据库升级完成；只能使用统一仓库。旧来源映射供显式定位与清理使用，不能把一个未知旧数字 ID 当作新 planId。

## 5. 完成与重复语义

- 单次计划：完成设置 isCompleted=true、completedAt=当前 Instant；重复点击不改写完成时间，撤销清除当前完成状态和 completedAt。
- 重复系列：使用同一完成字段表示整个系列结束。保存后停止展开后续未完成日程、排程及投递，不删除重复规则、来源记录或取消例外。
- 已完成系列在完成记录中显示一次，并标明“整个系列已完成”；查看详情保留原规则，不推断每次过去发生都实际执行过。
- 撤销完成恢复原规则，仅重新安排当前时间之后的合格提醒，不集中补发已错过的发生或提醒。不重新以今天为重复锚点，不恢复已取消例外。
- 日历在“显示已完成”时：单次计划仍放在其实际日期，完成系列以一条完成标记放在 completedAt 所属日期；不批量生成所有历史/未来已完成实例。
- 编辑已完成计划不自动撤销完成，日期改变不自动产生提醒；清空/恢复数据库后旧操作仍受维护世代保护。

## 6. 页面与统计

沿用日子芽原生卡通手账主题、系统字体、浅/深色、圆角导航与轻量反馈。无示例业务数据，无空占位入口。底部四入口为计划、打卡、订阅、设置。

计划模块包含：

- 列表：首页分类“全部 / 待办 / 日程”，默认未完成；状态筛选“未完成 / 已完成 / 全部状态”。搜索标题/备注，保留优先级和标签筛选；支持创建时间、截止/发生时间、优先级排序。保留今天/明天/本周/全部日期筛选；非全部日期时只显示与相应窗口匹配的有日期事项，无日期分类显示日期筛选不适用，不把无日期项假装成今天。无日期项的日期排序位置固定在有日期项之后，并有稳定 ID 次序兜底。
- 详情/编辑：共用标题、备注、优先级、标签、完成操作；按时间模式展示截止或区间/全天字段；地点、参与者、颜色、重复和单项提醒为日程参数。展示保留而未编辑的自定义参数，不把隐藏字段抹掉。
- 日历：仅日期事项进入月/周/日视图；DEADLINE 按截止日显示，不做区间冲突；TIMED / ALL_DAY 按窗口展开和取消例外过滤。周/日首批可沿用当前按日期事件列表，不将其宣称为原需求的完整小时拖拽时间轴。
- 冲突：仅真实区间和全天计划参加现有冲突确认，已完成及 NONE 不阻塞。修改表单或冲突集合变化后重新确认，不直接保存旧确认。
- 统计：独立统计页；全库总体完成率为完成计划数 / 全部计划数，空集显示 0 和“暂无计划”；重复系列只计一条。搜索和当前列表状态筛选不改变这个总体分母。

今日完成数按 completedAt 在当前展示时区的本地日期计算，包含当天完成的长期待办。逾期数仅计未完成的非重复日程：DEADLINE 在 dueAt 过去后或 dueDate 当天结束后，TIMED 在 endAt 过去后，ALL_DAY 在结束日期过去后计入。重复系列不因最初锚点已过去而永久逾期，不在首批提供逐次执行率。

“今天的日程”只含真实时间窗口与今天相交的计划；无日期长期待办不进入该集合。统计文案明确区分今日完成、今天日程、全库完成率。不从已完成系列推算虚构逐次打卡率。

列表/日历/详情/编辑/统计共用统一身份。完成或添加日期后保留当前筛选，明确提示已移到相应分类，不在编辑未保存时隐式跳页。切 Tab、旋转、通知点击、维护和备份操作继续保护现有草稿。

## 7. 提醒与设置兼容

新的设置只显示“计划提醒”与现有“订阅提醒”；打卡提醒没有实现，不增加假开关。计划编辑页控制单项提醒及提前分钟。投递资格是总开关、单项开关、有效时间、未完成、当前世代、当前重复例外和系统权限的交集。

旧开关组合的迁移：

- planReminders 初始化为旧 todoReminders OR scheduleReminders；两者均关闭则总开关关闭。
- 旧待办的单项 reminderEnabled 继承旧 todoReminders；原截止提醒配置为 15 分钟，即使无日期也保存这个单项偏好，但 NONE 模式不排程。
- 旧日程的单项 reminderEnabled 继承旧 scheduleReminders，原 reminderMinutes 原样保留；空分钟不排程。
- 旧版不实际支持的全天提醒，不因已有 reminderMinutes 自动启用；迁移记录的单项开关关闭，显示原因，可由用户在新版明确启用。
- 总开关重新打开不会自动改写原本关闭的单项开关。新计划默认提前 15 分钟，编辑页明确展示；总开关关闭时提示不会投递。

提醒锚点：DEADLINE 的 Instant 截止点；仅日期截止为该日期在计划时区的 09:00；TIMED 为开始时间；ALL_DAY 为发生起始日在计划时区的 09:00，再减提前分钟。仅排程未来触发点；若提前时间已过，不追补历史触发。保留 LocalDate 语义并覆盖夏令时和时区改变测试。

计划使用新的提醒命名空间与明确 planId/世代/发生标识，不与订阅或旧两类 PendingIntent 共用身份。完成、删除、变更时间、关提醒和模式变为 NONE 后撤销旧排程及通知；Receiver 在发通知前从 Room 重新验证全部资格，不能仅相信 Intent 的标题/时间。

升级后在应用、包更新/重启事件和 Worker 初始化执行可重试校准：按来源映射与旧库存清理两类旧闹钟/通知，再排统一计划及订阅。即使清理失败，旧 Receiver 也只能拒绝旧协议/世代，不发送第二条提醒、不写新库；清理失败明确报告并请求后台重试。

旧通知点击可安全打开计划首页并提示原通知已失效，不能借旧 ID/令牌直接编辑新记录。新通知直达统一详情，等待当前草稿保存或关闭；消费事件不因旋转重放。通知权限拒绝仍可离线 CRUD，精确闹钟不可用继续非精确兜底。

## 8. 架构、维护与错误处理

- `domain/plan`：Plan、时间/完成规则、仓库接口、CRUD/转换/完成/统计/发生计算用例；不依赖 Compose、Room 或 Android UI。
- `data/plan`：实体/DAO、PlanRepository 实现、映射和旧数据转换；只有数据实现访问 DAO。迁移和旧备份转换共享纯字段映射规则，不用旧 ViewModel 做数据迁移。
- `ui/plan`：列表/日历状态的 PlanViewModel，独立编辑/详情与统计 ViewModel；按职责拆分状态与组件，不把两个原大型 ViewModel 拼接为一个文件。
- `notification`：统一 PlanReminderScheduler、Receiver、校准和 Android 适配；通过领域接口读当前数据，不依赖 UI。
- Hilt 提供同一个 Room 单例、维护协调器和世代仓库；Worker 不自行开库或关闭应用数据库。依赖方向为 UI 使用领域接口，Data 实现领域接口，领域不反向依赖 Data。

StateFlow/Flow 驱动状态；列表、统计、编辑校验读同一事实来源。普通写入和真实 UI 结果发布继续经过维护许可与原世代核对；恢复成功推进世代，使旧草稿、通知和文件回调失效。维护取消/失败保留草稿；被拒绝的写入不排队自动重放。

同一计划的完成/编辑/日期转换在事务内保存，拒绝已删除记录的旧表单复活。写入失败保留输入并提示；数据库已保存而闹钟失败时明确“已保存，但提醒设置失败”，不允许再次插入同一新建草稿。读取失败禁用危险写入、导出和伪造统计，不用空列表冒充读取成功。

## 9. 备份格式 v2 与旧文件

新版只导出 formatVersion 2 / schemaVersion 6，包含统一 plans、标签关系、例外、来源映射、打卡/订阅全部数据及新设置。用新的明确字段契约代替旧“十表 75 字段”假设；外部字段不能直接成为 SQL 表名/列名。

旧 formatVersion 1 / schemaVersion 5 继续可导入：

1. 在受限私有临时输入上识别版本，以旧版严格字段契约检查原 JSON、SHA-256、类型、完整关联与限制。
2. 原文件完整通过后，在内存/临时受限表示中执行与数据库迁移相同的双来源映射、计划/关系/设置转换；不把未经转换的旧 payload 交给新 DAO。
3. 验证转换后的 v2 payload，展示新库将恢复的真实数量及旧版转换说明；未知版本、字段缺失/新增、重复键、校验失败、孤儿/环或溢出均拒绝，不忽略未知字段。
4. 对现有库另存并验证 v2 保护备份，最终独立确认后，单个 Room 事务完整替换；取消、验证失败和事务失败不修改当前库。

v2 严格检查新版主键、时间模式、关联和设置。迁移与恢复保留原文本及 Long 精度；现有已接受的历史完成字段组合允许原样保存，新写入才强制完整状态转换规则，不在导入时自行“修复”历史值。

旧文件校验其原始 payload，不以转换后的 hash 与旧 hash 比较；新导出重新计算新格式 hash。格式 v1 兼容不意味着旧 App 能读取 v2 或能安全降级到 v5。不得在新库上安装旧版后启用 destructive downgrade。

保持现有 64 MiB / 100,000 业务行边界；转换后的业务行（含来源映射）同样计入限制，增加的映射行使超限时明确拒绝，不截断。大型本地数据库迁移不套用外部文件的行数上限，但不能无限预生成重复实例。

继续采用完整替换而非合并，不导入备份携带的本机世代；清空业务数据保留设置。明文隐私确认、关闭后重读导出校验、文件取消/失败、临时文件所有权、保护来源 URI 边界和原有文件提供方限制继续有效。

## 10. 版本、交付顺序与验收

完成并验收 V1 统一功能后修改 versionName=1.0.0、versionCode=3。中间迁移/仓库子批不以一个不可运行的“V1 完成版”交付，不换包名，不为方便覆盖安装生成新签名。1.0.0 产品版本不自动等于应用商店正式发布资格。

开发顺序（不是本次已执行的实现计划）：

1. 明确迁移/字段契约与测试装置，再完成 v6 实体、迁移、统一仓库和规则。
2. 完成 v2 备份及 v1 转换、维护/提醒身份与完成系列行为，确保数据维护覆盖新表。
3. 接通统一列表、编辑/详情、日历和统计，替换导航和设置，删除正常运行路径中的旧业务实现，仅保留必要的旧文件/Intent 兼容代码。
4. 进行跨模块完整回归、覆盖安装、无障碍、体积与性能测量，更新 README、版本与验收记录，再按用户授权提交/推送、发布预览。

每批补测试和真实验收记录，不能把设计文档或子批编译通过当作整个 V1 完成。无完整统一链路前不开放空入口，也不能通过先删旧页面交付丢功能的中间 APK。

最低验收清单：

- v1/v2/v3/v4/v5 各历史 schema 均能通过完整迁移链到 v6，新安装直接 v6；同旧 ID、Long 极值、父子/标签、跨时区/全天、多种重复/例外、原完成/排序字段均逐值正确。
- 无效源、孤儿、环、设置/世代损坏、插入/校验故障导致回滚，原库及版本保持可恢复；打卡/订阅逐字段不变。
- NONE 与 DEADLINE 转换、身份不变、列表归类、日历显示、不虚构区间、隐藏字段保留；CRUD/完成/撤销/重复系列一次完成/删除保护。
- 今日完成、总体完成率、逾期和重复去重的确定性 Clock/Zone 测试；不会把全部长期目标每天计入今天日程。
- 旧四种总开关组合与单项提醒迁移、空分钟/全天边界、模式切换、重启/时区/DST/权限、Receiver 延迟、旧 Intent、重复投递和旧数字 ID 重号安全。
- v2 无损往返、v1 严格验证再转换、未知版本、hash/类型/字段/关系/限流错误、保护备份与原子恢复、维护和旧草稿/通知/文件回调回归。
- Compose 真实新增/分类转换/勾选/撤销/过滤/编辑错误/统计/导航与读屏，320dp 和 200% 字体、浅/深色；不插入假业务记录。
- 独立不含个人数据的测试设备执行覆盖安装与完整 instrumentation；升级前后合成记录数量与字段一致。不得在真实用户库上执行会卸载应用的 connectedAndroidTest。
- JVM、设备测试、Debug/androidTest/Release 构建、lint、APK 签名与体积检查；明确 warning、不支持的设备/功能和真实未验收项。

历史 669 JVM / 57 API 35 设备测试是 V0.1.1 / main 基线证据，不是 V1 的结果。V1 实际测试数量与通过状态必须由后续命令和报告确定。
