# Phase 1 Todo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a compilable Android Phase 1 MVP with an offline Room-backed todo flow, tag and priority filtering, basic statistics, local deadline reminders, dark theme support, and no placeholder pages for later modules.

**Architecture:** A single-activity Compose app uses `ui -> domain -> data` dependency direction. Room is the business-data source of truth; repositories expose `Flow` and suspend operations to use cases, and a `TodoViewModel` reduces them into immutable `StateFlow` UI state. Notification scheduling is isolated behind a scheduler and a broadcast receiver so it can be tested independently of screens.

**Tech Stack:** Kotlin, Android Gradle Plugin, Jetpack Compose Material 3, Room, Hilt, Kotlin Coroutines/Flow, WorkManager, AlarmManager, JUnit.

**Spec:** `android-app-prompt.md`, sections 零, 二, 三.1, 四.1, 五, 六, 八, 十一 Phase 1, 十二.

## Global Constraints

- Current implementation is native Android with Kotlin + Jetpack Compose + Material 3.
- Phase 1 exposes only the implemented Todo and Settings entries; no Calendar, Subscription, or Habit placeholder screens.
- All business data is stored locally in Room and remains usable without network access.
- Persist instants as `Instant` and monetary values, when later needed, as exact minor-unit integers; do not use `Double` for persisted money.
- UI does not access DAOs directly; ViewModels depend on use cases/repository contracts.
- Room schema changes use explicit migrations; no destructive migration.
- Notification permission denial must not block CRUD use.
- Release signing material must not enter source control.
