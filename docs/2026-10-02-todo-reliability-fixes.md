## 实现与数据保护

| 已批准问题 | 实现 |
| --- | --- |
| 截止时间改为过去后旧提醒仍触发 | 排程先取消旧闹钟，再决定是否创建新闹钟；升级时兼容清理旧无 data URI 的 PendingIntent。新 URI 保留完整任务 ID，广播携带排程时的截止时间。 |
| 接收器只信任旧广播标题 | 异步从 Room 仓库读取当前任务，核对存在、未完成、截止时间仍匹配，且处于截止前 15 分钟至截止时间的窗口；通知采用数据库最新标题。拒绝无校验信息的旧格式广播。读取/通知失败不崩溃，后台读取限时且释放广播生命周期。 |
| 日期选择器初始化 UTC 偏差 | 将截止 Instant 转为系统时区本地日期，再转换为 DatePicker 使用的 UTC 午夜；确认时保留本地时间。 |
| 通知打不开被筛选隐藏的任务/覆盖草稿 | 按 ID 从仓库读取，不依赖当前列表；已有草稿保留，表单显示等待通知目标，保存或关闭后处理。延迟查询期间草稿打开后再关闭，仍可交付；旧等待目标保留原 token，不能覆盖新通知。Activity 持有同一个待办 ViewModel，跨模块返回与旋转不创建另一份待办草稿；导航使用可消费 token 并移除已接收的 Intent extra。通知点击替换升级前的旧 PendingIntent，复用既有 Activity。 |
| 数据库成功而提醒失败导致重试插入 | 成功持久化后关闭新建草稿，提醒失败明确提示已保存；写入失败保留草稿并在编辑框内显示错误。拒绝重复保存/提交期间编辑或关闭。编辑以数据库当前对象为基准保留完成状态、完成时间、创建时间、父 ID 与排序信息；已删除目标不复活。 |

`TodoOperationCoordinator` 沿用现有订阅模块的进程内协调模式，覆盖待办 ViewModel 的读改写/闹钟副作用、接收器的读到通知、重启补排程和 Worker 校准，避免校准的旧快照覆盖刚保存的新提醒。Coordinator 不是数据库、不会持久化第二份业务数据。

Room 写入和闹钟副作用仍在 IO 调度器，提交成功后的草稿清空/等待目标交接、写入失败后的草稿恢复转到 Main，与通知查询结果和 UI 编辑变更串行。通知结果判断草稿是否打开与写入等待目标使用同一次原子状态更新，不会把等待目标附到已关闭的表单。

Room 仍为 v4，数据库定义与 schema 无变更，不新增迁移，不清库、不使用 destructive migration。没有新增依赖/新模块入口/假数据，未更改需求文件，也不提交 SDK 路径、代理、密钥或个人记录。

## 未完成与已知限制

- 无连接设备/模拟器，不能将 Robolectric、构建 APK 或静态检查等同于设备验收。真实 Hilt Activity/接收器注入、冷启动/旋转/连续点击、Android 13+ 通知权限、精确闹钟授权变化和厂商后台限制仍待设备验证。
- 新增实际 Activity 测试须在隔离的测试设备执行；不写入待办业务行，不应对个人日常数据库运行整个仪器测试集。源码中的 Hilt 所有者接入已编译，但没有设备运行证据。Worker/重启协调器接入仍以代码复核为主；本批新增的并发执行测试直接覆盖 ViewModel 与接收器。
- 拒绝旧格式广播以避免错误提醒；升级后通过既有启动/重启/每日校准机制重建有效闹钟。校准完成前，未被重新排程的旧闹钟不再发通知，可能漏掉一次提醒。已过截止时间的不补发历史通知。
- 本批没有持久化“已投递”状态，恶意重复发送完全相同且仍有效的内部广播不保证只调用一次通知；系统通知依旧使用确定性 ID。没有新增提醒设置重试按钮；已保存记录仍可重新编辑保存，后台校准也会补排程。
- Activity/ViewModel 内草稿和待查看事件不承诺系统杀进程后的恢复。本批也不改变已发布通知的撤回行为或待办统计口径。
- 日程提醒、重复续排、冲突窗口、编辑元信息/自定义参数、无效提醒分钟和按小时时间轴仍待后续批次；其他模块缺失功能、Phase 5、Wrapper/发布签名/SDK 要求、隐私备份规则、国际化与性能/适配验收仍见第一批报告，未在本批提前实现。
- 既有 AGP/Kotlin/KAPT、Schedule 协程 opt-in、标签外键索引及 Robolectric SQLiteMode 弃用警告仍存在；本批不重构无关配置或升级 SDK。
